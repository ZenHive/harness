## Observations (no change made)

- **`Harness.CodeSearch.Server` runs query/index funs inside its mailbox.** This is the explicit design — it serializes access to the single DuckDB connection and avoids per-query process boot. A side effect worth noting: a query fun that *raises* (rather than returning `{:error, _}`) crashes the GenServer and drops the cached QuackDB server + dynamic repos for *all* index keys; the supervisor restarts it and resources rebuild lazily on next query, so impact is bounded (cold-path dashboard usage, rebuildable state). Exograph/repo errors return tuples on the paths exercised, so this is latent, not an active bug. Not filed as a task — deliberate tradeoff, low impact.
