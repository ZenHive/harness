## Found / Fixed

  run-detail readability change (c3ada3b) had a `[Unreleased]` entry — the newest entries stopped
  at Tasks 299/300/301. Added two `### Added` entries matching the existing house style.
- **Atom-table leak in `Harness.CodeSearch.start_repo/2` (filed Task 304, not fixed here).**
  The dynamic Exograph repo is registered with `name: :"#{repo}_#{System.unique_integer([:positive])}"`
  (code_search.ex:339), minting a fresh, never-GC'd atom on every invocation. Every query
  (`definitions`/`callers`/`callees`/`duplicates`/`refresh`) flows through `with_repo` → `start_repo`,
  so a long-running harness node grows the atom table unboundedly toward exhaustion. Sobelow flags it
  as `DOS.BinToAtom` (low_confidence). This is a behavioral fix needing its own review/test cycle, so
  it is filed as **Task 304**, not patched in this docs-only audit commit.
