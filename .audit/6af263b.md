## What was delivered

One focused mechanical fix (the rest of the range are roadmap status markers and dispatchability flips, which touch only `roadmap/{tasks.toml,data.json}`):

- **Task 240 (model pin to Invocation).** The latent bug: `requested_model` (sourced from Item.model at dispatch, stored in run `data`, visible in `status_snapshot`, threaded to `LogRecord`/`ResultStore`, and already declared on `%Invocation{}` and `AgentAdapter.model_args/1`) was never copied into the two Invocation builders that actually drive implementer (and recovery) agents. Result: `--model` was silently dropped for all six adapters; task-level pins (e.g. `model = "claude-opus-4-8-thinking-high"`) had no effect and every run used the adapter default. The fix adds the two lines in `run.ex` (`invocation/3` and `recovery_invocation/1`). Reviewer invocation intentionally stays unpinned (cross-family). Added two targeted tests in `run_test.exs` (pinned value captured + unpinned case) using a new `:capture_model` FakeAdapter clause that commits `agent_model.txt` for git-show assertion post-settle. Commit message records the live cursor confirmation.

Files with meaningful churn (roadmap markers excluded): `lib/harness/run.ex`, `test/harness/run_test.exs`, `test/support/fake_adapter.ex`.
