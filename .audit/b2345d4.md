## What was delivered

Focused agent-gate hygiene for GitHub credential isolation (the rest of the range is the mechanical "task -> done" marker that touches only roadmap data files):

- **Task 188 (GH_TOKEN / GITHUB_TOKEN scrub + GH_CONFIG_DIR for in-run).** In-run agents (implementer, reviewer, recovery) must not be able to use the operator's `gh` auth to e.g. `gh pr create` or read private repos. Task 186's push-neuter closed the `git push` vector via worktree-scoped remote/sentinel, but explicitly left the `gh` vector open (gh uses its own token/config, not the git credential). The fix:
  - At `Harness.Run` init time, caller-provided `env` is passed through `scrub_github_auth_env/1` which forces `GH_TOKEN` and `GITHUB_TOKEN` to the `false` sentinel (existing convention for "unset at spawn time").
  - The three Invocation builders that drive autonomous agents inside a run (`invocation/3` for implementer/steer, `reviewer_invocation/1`, `recovery_invocation/1`) now use `in_run_env/1` (or wrap it) instead of raw `data.env`. `in_run_env/1` does `Map.put(..., "GH_CONFIG_DIR", Path.join(worktree, ".harness/gh-config"))`.
  - This points `gh` at an isolated (initially absent or empty) config dir inside the run worktree, so `~/.config/gh/hosts.yml` (and any tokens) are never visible.
- New private helpers carry `@spec`s (per project rule for defp too). Module-level comment records the "scrub alone is not sufficient" assessment.
- Test: "in-run invocation env strips ambient GitHub auth for gh" (inside the lifecycle describe, sibling to the Task 240 model-pin capture tests). Uses a new `:capture_github_env` FakeAdapter clause that dumps the three vars into a committed `agent_github_env.txt`; post-settle `git show` asserts tokens are empty and `GH_CONFIG_DIR` is the worktree-local path (even when caller tried to inject a leaky one).
- FakeAdapter: added the capture clause + explanatory comment parallel to `:capture_model`.
- CHANGELOG: detailed bullet placed directly after the Task 186 push-neuter paragraph it closes; records the mechanism, the decision, the scope (only the three in-run roles), and that the git sentinel remains the separate path.

Files with meaningful churn (roadmap marker excluded): `CHANGELOG.md`, `lib/harness/run.ex`, `test/harness/run_test.exs`, `test/support/fake_adapter.ex`.
