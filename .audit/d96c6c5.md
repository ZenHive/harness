## Observation (not a defect, not filed)

In `result_store/postgres.ex` the on-conflict merge for `review_concerns` uses
`COALESCE(NULLIF(EXCLUDED.review_concerns, '{}'::jsonb), ?)`, mirroring the
facets/skills pattern. But `encode_freeform_list` always emits `%{"$list" => [...]}`
(never bare `'{}'`), so the `NULLIF` against `'{}'` can never fire for concerns — the
"empty re-write preserves the prior value" semantic that the facets/skills lines get
does not apply to concerns. Harmless in practice (concerns are written once at settle;
re-settle with the same value is idempotent), and plausibly intentional. Noting it for
the record; no forward fix and no rmap task — fixing it requires a judgment call on the
intended re-settle semantics that the reviewer already accepted.
